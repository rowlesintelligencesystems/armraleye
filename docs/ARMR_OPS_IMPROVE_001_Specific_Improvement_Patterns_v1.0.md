# ARMR ALEYE — Specific Improvement Patterns

**Document ID:** ARMR-OPS-IMPROVE-001  
**Version:** 1.0  
**Status:** ACTIVE  
**Parent:** ARMR-OPS-BUILD-001 v1.1  
**Purpose:** Concrete, repeatable patterns that improve every subsequent manual and product.

---

## 1. Structure Improvement Patterns

### 1.1 The 11-Point Spine (Non-Negotiable Base)
Every document now follows:
Hero → Logos → S'Cara Avatar → TOC → Intro → Deep Body → System Integration → Infographics → Outro → Outcomes → Brand Wrap

**Improvement effect:**  
Operators orient in under 60 seconds. Nothing critical is ever missing. Documents feel like one family.

### 1.2 Depth over Brochure
Early drafts were thin. The improvement pattern is:
- Force a real “Body (Deep Research)” section
- Require at least one practical tool (checklist, template, workflow, failure matrix)
- Require explicit “What this is / What this is not”

**Improvement effect:**  
Documents become usable on day one instead of needing verbal explanation.

### 1.3 Outcomes Section as Closer
Adding a dedicated Outcomes section (claims-safe) forces clarity on “what success looks like.”

**Improvement effect:**  
Prevents vague endings and keeps the product tied to observable results without crossing into guaranteed income/ROI language.

## 2. Visual Improvement Patterns

### 2.1 Locked Asset Only Rule
Only use:
- Winged-S + halo logo
- Approved S'Cara renders
- Official Hamsa variants (cyan / gold / hybrid / minimal)
- Locked Grok profile set

**Improvement effect:**  
Zero brand drift. Every PDF looks like it belongs to the same system.

### 2.2 Color Discipline
- Navy ground only
- Gold for hierarchy
- Cyan for emphasis and links
- Ivory for body text

**Improvement effect:**  
Instant visual recognition and professional density without clutter.

### 2.3 Hero Graphic Accuracy
Hero must depict the actual product (not a generic abstraction).

**Improvement effect:**  
Buyer/operator immediately understands what they are looking at. Reduces “what is this?” friction.

### 2.4 Infographic Density
Replace long paragraphs with:
- Phase cards (G0–G4 style)
- Process flows (Accept → Pay → Unlock)
- Comparison tables
- Score breakdowns

**Improvement effect:**  
Faster comprehension and higher perceived value.

---

## 3. Content Improvement Patterns

### 3.1 Doctrine as Architecture (Not Decoration)
Doctrine sequence appears early and is applied to the product’s operating logic.

**Improvement effect:**  
Ethics become structural instead of optional. Prevents claims drift.

### 3.2 Two-Panel Claims Boundary
Always show Allowed vs Forbidden in a clear visual panel pair.

**Improvement effect:**  
Operators and marketers have an unambiguous reference. Reduces accidental prohibited language.

### 3.3 Confirm Gates Called Out
Whenever match or push is described, explicitly name `confirm_scan` and `confirm_push`.

**Improvement effect:**  
Reinforces Zero Trust / human-in-the-loop discipline across all engine documentation.

### 3.4 System Integration Section
Every product must answer:
- Which engines does this support or depend on?
- Which locked manuals and assets does it connect to?
- Where does the operator subscribe or purchase?

**Improvement effect:**  
No orphan products. The ecosystem stays coherent and commercially connected.

## 4. Commercial Improvement Patterns

### 4.1 Subscription Surface Always Present
Include the live plan table and storefront link:
- PIE $149/mo
- PIE Heavy $249/mo
- Engine Stack $399/mo
- Members $29/mo
- https://www.armraleye.com

**Improvement effect:**  
Every manual becomes a potential conversion surface without hard selling.

### 4.2 Related Product Mapping
List the supporting products with their roles and price/access model.

**Improvement effect:**  
Natural cross-sell and clearer customer journey without aggressive tactics.

## 5. Delivery & Memory Improvement Patterns

### 5.1 Full Lock Sequence
1. Executive PDF
2. Upload to Drive → capture link
3. Commit Markdown to repo
4. Update MSOT (if architecture changed)
5. Update Running File
6. Embed Drive link inside the document

**Improvement effect:**  
Single source of truth survives context resets and team handoffs.

### 5.2 Self-Audit Before “LOCKED”
Run the full checklist (especially the 11 mandatory elements + claims + visual pass) before declaring locked.

**Improvement effect:**  
Prevents half-finished documents from entering the system of record.

### 5.3 Pattern Log as Living Memory
After each major build, extract one new improvement pattern and add it here.

**Improvement effect:**  
The standard itself gets smarter with every product.

## 6. Anti-Pattern Kill List (Active)

These caused friction or quality drops — now explicitly banned:

| Anti-Pattern | Replacement Pattern |
|--------------|---------------------|
| Missing TOC | Mandatory TOC |
| Missing S'Cara avatar | Mandatory locked avatar |
| Thin brochure body | Deep research body + practical tools |
| No system integration | Dedicated Support Systems section |
| No subscription links | Always include plan table + storefront |
| Unofficial imagery | Locked assets only |
| Doctrine as slogan | Doctrine as operating architecture |
| Vague ending | Explicit Outro + Outcomes |
| Forgotten MSOT/Running File update | Full lock sequence |

## 7. How Improvement Compounds

Each new manual now starts from a higher floor:

- Structure is already decided (11 points)
- Visual system is already decided (locked assets + palette)
- Ethics are already decided (doctrine + claims panels)
- Commercial surface is already decided (subscription links)
- Delivery process is already decided (PDF → Drive → Repo → MSOT → Running File)

**Result:**  
Energy goes into depth, accuracy of hero graphics, quality of infographics, and precision of system integration — not into re-deciding basics.
